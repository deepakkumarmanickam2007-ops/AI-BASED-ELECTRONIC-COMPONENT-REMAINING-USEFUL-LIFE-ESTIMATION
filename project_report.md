# Project Report: AI-Based Electronic Component Remaining Useful Life Estimation

## Abstract
Electronic components degrade over time because of operating temperature, electrical load, ripple, vibration, and material aging. Unexpected failures can increase downtime and maintenance cost. This project demonstrates a machine-learning workflow for estimating remaining useful life (RUL) from time-series operating measurements. A synthetic component-aging dataset is generated, temporal and stress-related features are engineered, and Random Forest and Gradient Boosting regression models are compared. The models are evaluated on components held out from training using mean absolute error (MAE), root mean squared error (RMSE), and coefficient of determination (R²). Graphs show predicted versus actual RUL, residual error, and feature importance. Since the bundled dataset is simulated, results demonstrate the methodology and are not evidence of field-level accuracy.

## 1. Introduction
Remaining useful life is the estimated operating time or number of cycles before a component reaches a defined end-of-life (EOL) condition. RUL estimation supports condition-based maintenance by replacing components based on measured condition rather than a fixed calendar schedule. Electronic components can exhibit gradual drift in equivalent series resistance (ESR), capacitance, efficiency, temperature, and ripple.

## 2. Problem statement
Develop a regression pipeline that estimates RUL or degradation from time-series operating conditions, compares predictions against known simulated outcomes, and identifies variables associated with degradation.

## 3. Objectives
1. Create a time-series dataset containing component condition and aging.
2. Preprocess data and engineer temporal/stress features.
3. Train Random Forest and Gradient Boosting regressors.
4. Evaluate on unseen component IDs to reduce row-level leakage.
5. Produce plots, metrics, a reusable model, and an interactive dashboard.
6. Discuss conditions associated with simulated degradation.

## 4. Dataset and provenance
The included dataset is generated by `src/generate_dataset.py`. It contains simulated component IDs, age cycles, ambient/case temperature, load, voltage, ripple, vibration, ESR, capacitance, efficiency, degradation index, failure flag, and RUL. The simulation introduces component-to-component variation and measurement noise. EOL is defined by each simulated component's terminal cycle. This is a synthetic dataset created for education and reproducibility, not measured hardware data.

## 5. Methodology
### 5.1 Preprocessing
- Load observations using Pandas.
- Sort by component ID and cycle.
- Replace invalid infinite values with missing values and impute numeric missing values using training-compatible simple medians in the current demonstration.
- Split by component IDs using `GroupShuffleSplit`; observations from one component do not occur in both training and test sets.

### 5.2 Feature engineering
Derived features include thermal stress above 40°C, squared normalized load, normalized ripple, normalized age, ESR-to-capacitance ratio, efficiency loss, rolling means, and first-difference trends for selected signals.

### 5.3 Models
**Random Forest Regressor:** combines predictions from many decision trees, reducing variance and modelling nonlinear interactions.

**Gradient Boosting Regressor:** sequentially adds shallow trees to reduce residual error. Huber loss is used to reduce sensitivity to larger residuals.

### 5.4 Evaluation
- MAE = average absolute difference between predicted and actual RUL.
- RMSE = square root of mean squared prediction error.
- R² = proportion of target variance explained by the model relative to a mean baseline.
The actual metric values are written to `outputs/metrics.csv` when `python run_project.py` is executed. Include those measured local results in the final submitted report; do not invent or pre-fill results.

## 7. Results and discussion
On the bundled synthetic dataset, the run produced the following held-out-component results (the exact values are also saved in `outputs/metrics.csv`). Compare MAE and RMSE first (lower is better); use R² as a complementary metric.

| Model | MAE (cycles) | RMSE (cycles) | R² |
|---|---:|---:|---:|
| Random Forest | 11.99 | 39.36 | 0.9865 |
| Gradient Boosting | 53.25 | 84.03 | 0.9386 |

Random Forest was selected by the lowest MAE on this run. These scores apply only to the generated synthetic dataset and should not be interpreted as real-hardware accuracy. Inspect `predicted_vs_actual.png`: points near the diagonal represent more accurate estimates. Inspect `residuals.png` for systematic over- or under-prediction. Use `feature_importance.csv` to identify which inputs the selected model relied on most.

High temperature, sustained load, increasing ripple, rising ESR, falling capacitance, and falling efficiency are plausible degradation indicators in the simplified simulator. Model feature importance indicates predictive association, not causation. Because the simulator itself encodes these relationships, performance on synthetic data may overstate performance on real components.

## 8. Applications
- Predictive maintenance demonstrations.
- Condition monitoring education.

- Comparing regression algorithms on time-series-derived features.

## 9. Limitations
1. Data is synthetic and cannot validate a real component's lifespan.
2. RUL depends on the simulated EOL definition and component-specific life.
3. A one-row dashboard prediction has limited temporal context.
4. Feature importance does not prove causality.
5. The model does not quantify prediction uncertainty.
6. Real component types require separate calibration and validation.

## 10. Future enhancements
- Replace synthetic data with public or lab-measured capacitor, battery, power-device, or inverter aging data.
- Use component-specific EOL thresholds and domain expert review.
- Compare XGBoost/LightGBM or sequence models if dependencies and data volume permit.
- Add time-series cross-validation, uncertainty intervals, and drift monitoring.
- Deploy the dashboard only after independent validation on representative field data.

## 11. Conclusion
The project implements a complete educational RUL estimation workflow: synthetic data generation, temporal feature engineering, component-level holdout, two regression models, quantitative evaluation, visualization, saved artifacts, and an optional Streamlit dashboard. It demonstrates how AI methods can support condition-based maintenance research. Real-world use requires measured aging data and rigorous validation.
